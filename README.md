# ChatMinutes: turning group chats into minutes and tasks

**PCAM ZG516 Applied Generative AI · Group Major Project (Assignment 1) · Dataset D3: SAMSum · Group 14**

ChatMinutes reads a group chat and returns three things: a short summary, meeting minutes in a fixed JSON format (key points, decisions, action items, sentiment), and the promised tasks logged in a simulated tracker with real due dates.

It runs on **Qwen2.5-1.5B-Instruct**, a small pretrained decoder-only LLM from Hugging Face, with **no fine-tuning**. All improvements come from prompting, decoding settings, output checks in code, and tool calling.

## Key design decisions

| Decision | What we chose | Why |
|---|---|---|
| Kind of model | Decoder-only (causal) LLM | Reads a chat, writes new text, and returns JSON and tool calls from a prompt alone |
| Which model | Qwen2.5-1.5B-Instruct | Fits a free T4 GPU, instruction-tuned, built-in tool calling, ungated, under 1 s per summary |
| Test set | 40 fixed test chats (seed 42), across chat lengths | A free GPU could not run all 815 for every experiment; a fixed set keeps runs repeatable |
| Prompt examples | Training split only | No test chat or its answer ever appears in a prompt |
| Adapting the model | Few-shot prompting, no fine-tuning | Style and length were the problem, and two examples fixed it; fine-tuning could weaken JSON and tool skills |
| Decoding | Greedy | Best ROUGE-L, the same answer every time, never broke the JSON |
| Output format | JSON with a Pydantic schema, code checks and one repair | A plain "give me JSON" prompt was 0% usable; schema-guided with checks gave 97.5% |
| Pipeline order | Write and check the minutes first, then log tasks | Doing both in one step gave wrong deadlines and invented tasks |
| Privacy and safety | Remove personal details first; a person reviews tasks | Private data never reaches the model; the injection test showed the model can be fooled |

## Main results (40 SAMSum test chats)

| System | ROUGE-L | Made-up names | Speakers mentioned | Format valid | Sec / chat |
|---|---|---|---|---|---|
| E1 baseline | 0.321 | 0% | 92.5% | 30.0% | 0.64 |
| Best prompt (V2 few-shot) | 0.409 | 0% | 83.5% | 77.5% | 0.40 |
| Final system (JSON minutes) | 0.334 | 0% | 72.9% | 97.5% (valid JSON) | 1.82 |

- Two examples in the prompt raised ROUGE-L from 0.321 to 0.409 and format compliance from 30% to 77.5%.
- Greedy or low-temperature decoding gave the best summaries; high temperature broke the output.
- A schema-guided JSON prompt with code checks gave valid minutes for 39 of 40 chats (0% with a plain JSON prompt).
- Tool calls were always well formed, but the model's judgement on deadlines was weak until the job was split in two.
- The main remaining weakness is finding every action item.

## How to run

1. Open `notebook/SAMSum_GenAI_Project_V1.3.ipynb` in Google Colab (**File → Upload notebook**) or Kaggle.
2. Select a GPU: Colab **Runtime → Change runtime type → T4 GPU**.
3. Run all cells (**Runtime → Run all**). The main experiments take about 20–30 minutes on a free T4 GPU.
4. The last cell zips everything in `outputs/` and downloads it.
5. Optional live demo: set `RUN_GRADIO = True` in Section 14.

All settings, including the random seed (42), are in the `CONFIG` cell near the top, so runs are repeatable.

## Data and privacy

SAMSum (Gliwa et al., 2019) contains chats written by linguists for the dataset, so it holds no real personal information. The app also removes phone numbers, emails, links and card numbers before a chat reaches the model, and the model runs inside the notebook, so no chat text is sent to an outside service. The phone number and email in the responsible-use test are placeholders.
